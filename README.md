# 캡스톤: 스마트폰 카메라 결합형 저비용 비파괴 당도 추정 기반 만감류 수확 적기 판정 보조기

만감류(한라봉·천혜향 등)에 근적외선을 비추고 과일 속을 거쳐 돌아온 빛을 값싼 멀티스펙트럼 센서로 재서, 자르지 않고 당도(Brix)를 추정해 수확 시기를 판단하는 프로젝트입니다. 센서를 과일에 붙이지 않고 가까운 거리(최대 12cm)에서 재므로 **센서와 과일 사이 거리**와 **과일 크기**를 보정 값으로 함께 기록해야 합니다.

## 개발 현황 (2026-11-03)

| 부분 | 상태 |
|---|---|
| 측정 거리·과일 크기 앱(이 저장소) | 완성, 갤럭시 Z 플립6 크롬에서 확인 |
| 근적외선 센서 연동 | 아직 안 함(하드웨어는 팀원이 제작 중, 센서 구매 완료) |
| 당도 추정 모델 | 코드 완성(`model/`), 가짜 데이터로만 검증. 실제 측정 데이터 기다리는 중 |

### 측정 앱이 하는 일

1. 「측정 시작」 → 30cm쯤 떨어져 과일을 화면 가운데에 두면, 화면 가운데에 가장 가까운 과일을 자동으로 찾아 따라감(「다시 선택하기」로 다시 찾기).
2. 다가가는 동안 여러 위치에서 본 윤곽을 한 구에 맞춰 **과일 지름(mm)** 확정(「크기 다시 재기」 가능).
3. 이어서 **카메라와 과일 표면 사이 거리**를 실시간 표시하고 12cm 안으로 안내(안이면 초록·진동, 너무 가까우면 「조금 멀리」).
4. 12cm 안에서 폰을 잠시 멈추면 **자동 촬영**(끌 수 있음). 이 순간이 근적외선 측정 순간에 해당.
5. 사진에서 윤곽과 거리 확인, 필요하면 과일을 터치해 다시 인식하거나 양 끝을 직접 지정 → 기록 저장(번호, 크기, 거리, 시각). 기록은 기기 브라우저(localStorage)에만 저장.

### 측정 원리와 기준 값

- **윤곽 인식**(`detect.js`): 가리킨 점에서 120방향으로 과일 색과 달라지는 경계점을 찾고, 구의 윤곽 원뿔(카메라→과일 중심 축과 같은 각도의 시선들)에 맞추며 튀는 점은 버림. 위에서 보면 가운데가 꼭지라, 찾은 윤곽을 감싸는 더 큰 윤곽이 있고 안쪽이 더 어두우면 바깥을 과일로 고름. 따라가기는 3프레임마다, 짧은 변 480px 이미지로.
- **크기**(`measure.js` `fitSphereViews`): AR이 알려 준 폰 위치·자세와 윤곽 원뿔을 여러 위치에서 모아 한 구(중심, 반지름)에 최소제곱으로 맞춤. 3곳 이상, 5cm 이상 이동, 최근 5개 값이 2% 안이면 확정.
- **거리**(`distanceFromCone`): 중심까지 = 반지름 / sin(원뿔 반각), 여기서 반지름을 빼 표면까지. 단순 비례식은 10cm에서 약 5% 짧아 쓰지 않음.
- **자동 촬영**(`distanceStability`): 12cm 안에 들어온 뒤의 거리 값 10개가 5mm 안이면 안정 → 촬영. 촬영 사진에서는 따라가던 원과 크기가 맞는 윤곽만 골라 거리를 다시 잼.
- 크기는 당도를 직접 알려 주는 값이 아니라 보정 값이라 과일을 구로 보고 지름 하나만 잼(가로·세로를 따로 재는 방식은 해 봤다가 뺌). 카메라로 색을 재거나 과일 옆에 기준 물체를 놓는 방식은 쓰지 않음.

### 확인한 것과 한계

- 폰에서 확인: 찾기·따라가기·크기·실시간 거리·자동 촬영·사진 거리·저장·다시 선택·직접 지정. 자로 잰 크기·거리와 앱 값이 일치함을 확인(수치 기록은 없음).
- AR이 폰 위치를 잘못 잡으면(특히 시작 직후) 크기가 크게 틀릴 수 있음(실제 약 50mm가 100.5mm로 나온 적 있음) → 「크기 다시 재기」로 대응. 6cm 정도만 움직여 잰 크기는 덜 정확함.
- 아주 가까이 가서 과일을 놓치면 다시 잡지 못할 수 있음 → 조금 떨어지거나 다시 선택.
- 가까이서 카메라 화면이 흐려짐: 웹(WebXR)에서는 AR 카메라 초점을 바꿀 수 없음(설치형 앱이면 가능). 윤곽으로 재는 값에는 영향 없음.
- ARCore를 지원하는 안드로이드 크롬에서만 동작. PC에서는 「AR 미지원」 안내만 나옴.

### 당도 추정 모델 (`model/brix.py`)

노트북에서 학습·평가하고, 결과는 「Brix = 절편 + Σ 계수 × 입력」 계수로 JSON에 저장(앱에서는 곱하고 더하기만 하면 됨).

1. **값 다듬기**: 반사율 = (광원 켠 값 − 끈 값) ÷ (같은 세션·방식 기준판의 켠 값 − 끈 값). 켠−끈으로 주변광, 기준판으로 그날 광원·센서 상태를 보정.
2. **입력**: 채널별 흡광도 log10(1/반사율) + **log10(거리)** + 지름. 빛은 거리에 따라 곱으로 줄어서(대략 1/거리²) 흡광도에서는 log10(거리)에 비례해 더해짐. 가짜 데이터에서 거리를 그대로 넣으면 비접촉 오차가 1.06 → 1.70 °Brix로 커짐. 기본은 근적외선 6채널(730–940nm), `--channels all`이면 18채널.
3. **모델**: PLS 회귀. **측정 1번 = 한 행**(반복을 평균하지 않음). 실제로는 한 번만, 12cm 안의 아무 거리에서 재기 때문. 반복을 평균하면 과일마다 평균 거리가 같아져 거리 영향을 못 배움(가짜 데이터에서 5·8·11cm 치우침이 +0.09 / −0.22 / −0.45 °Brix로 벌어졌음 → 바꾼 뒤 거의 0).
4. **평가**: 과일 단위 교차검증(같은 과일이 학습·평가에 함께 안 들어감). 오차는 「한 번 잰 값으로 맞힌 오차」이고, 반복 번호(=거리)별 오차·치우침도 출력. 성분 수도 안쪽 교차검증에서 골라 오차를 좋게 보이게 하지 않음. RMSE·치우침·R² 출력. 과일 30개 미만이면 믿기 어렵다고 표시.
5. **접촉/비접촉 비교**(`compare`): 과일 몇 개로는 당도 오차를 믿을 수 없으니 채널별 신호 세기, 주변광 비율, 반복 흔들림, 과일 구분(과일 사이 차이 ÷ 반복 흔들림), Brix 상관(과일 5개 이상)을 봄. 흔들림·구분은 거리 영향을 빼고 계산(빼지 않으면 반복마다 거리가 바뀌는 비접촉이 무조건 불리).

```
python -X utf8 model/brix.py compare 측정.csv
python -X utf8 model/brix.py train 측정.csv --mode noncontact --out model.json
python -X utf8 model/brix.py predict model.json 새측정.csv
python -X utf8 model/sample_data.py 가짜.csv     # 정답을 아는 가짜 데이터(수집 계획대로 400개 × 5·8·11cm)
python -X utf8 test/test_brix.py                 # 테스트
```

**한계**: 가짜 데이터의 숫자(오차 약 1.0 °Brix 등)는 제가 정한 가정에서 나온 값이라 실제 정확도가 아님. 실제 과일·센서로 다시 확인해야 함.

#### 수집 계획

- 과일 **400개**, 과일마다 비접촉 **3번**: 반복 1·2·3 = **5·8·11cm**(12cm 한도 안을 고르게). `distance_mm`에는 정한 거리가 아니라 앱이 잰 실제 거리를 적음.
- 비접촉만 잼(접촉 측정은 하지 않음). 재는 부위는 따로 정하지 않음.
- 5cm는 실물로 해 보고 앱이 윤곽을 못 잡으면 다른 거리로 바꿈.

#### 측정 데이터 형식 (CSV, 하드웨어 쪽과 맞출 것)

한 행 = 한 번 측정. 기준판(흰색 반사판)도 같은 파일에 `kind=white`로 세션·방식마다 한 번 이상.

| 열 | 내용 |
|---|---|
| `kind` | `fruit` 또는 `white` |
| `session` | 기준판을 잰 묶음(같은 날·같은 설정). 과일은 같은 세션·방식의 기준판으로 보정 |
| `mode` | `noncontact` 또는 `contact` |
| `fruit_id`, `rep` | 과일 번호, 반복 번호(기준판 행은 비워도 됨) |
| `distance_mm`, `diameter_mm` | 측정 앱 값(접촉이면 거리 0) |
| `brix` | 굴절당도계 실측(모르면 비움) |
| `on_410` … `on_940` | 광원 켠 상태 18채널 값 |
| `off_410` … `off_940` | 광원 끈 상태 18채널 값(같은 위치·같은 센서 설정) |

채널(nm)과 SparkFun 라이브러리 글자: A410 B435 C460 D485 E510 F535 G560 H585 R610 I645 S680 J705 T730 U760 V810 W860 K900 L940.
